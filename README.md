# SIMS Doctor v1.0 — Sprint2-1 Design Package

## Purpose

This package fixes the Sprint2-1 boundary:

1. Receive `SIMS_DOCTOR_SINGLE_CASE_REQUEST_V1`
2. Validate and normalize the request
3. Issue Request ID and Case ID
4. Register the case
5. Create `SIMS_DOCTOR_MEDICAL_RECORD_V1`
6. Return an acceptance or rejection result

Diagnosis, 365-day Search Console acquisition, SERP comparison, and referral generation are outside this package.

## Important compatibility note

The four contract names were already approved before this package was created, but their exact source files were not available during generation.
Therefore, the schemas in `contracts/` are **provisional compatibility schemas** based on the approved Sprint2-1 specification.

Before implementation is frozen, compare these schemas against one real JSON generated by the current SIMS Blog Manager.
Do not silently change the SBM output to match this package.

## Contract boundary

- External input: `SIMS_DOCTOR_SINGLE_CASE_REQUEST_V1`
- Internal source of truth: `SIMS_DOCTOR_MEDICAL_RECORD_V1`
- External result: `SIMS_DOCTOR_SINGLE_CASE_RESULT_V1`
- Future treatment referral: `SIMS_DOCTOR_WRITER_REQUEST_V1`

## Sprint2-1 completion condition

- Valid request accepted
- Invalid request rejected with stable error code
- Request ID generated
- Case ID generated or an active case reused
- Medical record initialized
- Registry and medical record stay consistent
- Partial data is not committed on failure
